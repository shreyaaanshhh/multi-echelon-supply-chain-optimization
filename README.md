# Multi-Echelon Supply Chain Network Optimization

An end-to-end supply chain analytics project: cleaning real, messy order and freight-rate data, then formulating and solving a Linear Programming model to minimize distribution cost across a real plant-to-customer network.

## Problem Statement

Given a set of plants with limited capacity and a set of customers with known demand, determine how to allocate shipments from plants to customers so that total logistics cost is minimized, while respecting each plant's capacity.

## Data Source

[Kaggle: Supply Chain Logistics Problem](https://www.kaggle.com/datasets/anisseezzebdi/supply-chain-logistics-problem) :- a real Excel workbook with order-level transactions, carrier freight rates, and plant capacities.

## Approach

1. **Data cleaning** :- merged 9,215 raw orders with carrier freight-rate tables on carrier, port, and weight bracket. Retained 6,991 orders (~76%) with a verified real shipping rate; excluded orders with no matching rate data, with the exclusion reasoning documented in `docs/methodology.md`.
2. **Cost & demand construction** — built a real, data-derived cost matrix (68 plant–customer shipping lanes) and per-customer demand from the cleaned order data.
3. **Capacity reconciliation** :- source plant capacity figures were on a different scale than order volumes; resolved via proportional scaling that preserves each plant's relative capacity share.
4. **LP optimization** :- formulated and solved a linear program in PuLP to minimize total shipping cost under plant capacity and customer demand constraints. Added a penalized shortfall variable to gracefully handle customers whose demand could not be fully met by their connected plants, rather than forcing an infeasible hard constraint.

## Results

- **97.77% of total demand fulfilled**, with total logistics cost of **₹2.11 crore (~$254K)**.
- Identified a **2.23% network coverage gap** - 9 of 42 customers were under-connected to plants with available capacity, a genuine structural insight from the data rather than a modeling artifact.
- Found that one plant (PLANT16) retained significant spare capacity while five others were fully utilized, a concrete capacity-rebalancing opportunity.

Full methodology, all assumptions, and step-by-step reasoning are documented in [`docs/methodology.md`](docs/methodology.md).

## How to Run

```bash
pip install -r requirements.txt
```

Run the notebooks in order:
1. `notebooks/01_data_cleaning.ipynb` — produces `data/processed/cleaned_orders.csv`
2. `notebooks/02_lp_optimization.ipynb` — builds the cost/demand/capacity tables, solves the LP model, and exports results
